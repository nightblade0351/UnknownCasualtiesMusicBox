# 未知伤亡音乐盒 · 命名规则（给 AI 的作业说明）

本文档描述「未知伤亡音乐盒」模组的 `data` 目录规范。**只要按本规则命名文件，模组即可自动识别全部事件音乐。**

参考样板：`data\内华达-Vicetone&Cozi Zuehlsdorff\`（本规则就是按它的目录结构定的）。

---

## 1. 目录结构

```
<游戏>\BepInEx\plugins\UnknownCasualtiesMusicBox\data\
├─ 音乐盒A\            ← 文件夹名 = 设置里显示的音乐盒名称
│   ├─ hall.mp3
│   ├─ choose_part.mp3
│   ├─ waiting_map_1.mp3
│   ├─ waiting_map_2.mp3
│   └─ ...
├─ 音乐盒B\
│   └─ ...
```

**硬性规则**

| 项 | 说明 |
|---|---|
| 一层深度 | `data\<音乐盒名>\<文件>`，不支持再嵌套子文件夹 |
| 文件夹名 = 选项名 | 设置下拉里显示的就是文件夹名本身，不支持别名/本地化 |
| 唯一性 | 同名（忽略大小写）只取一个；冲突会打日志并忽略 |
| 非法字符 | 含 `Path.GetInvalidFileNameChars()` 的文件夹会被忽略 |
| 名称自定 | 中文、空格、`&`、`-`、括号都可以，例如 `理由-Rad Cat` |

---

## 2. 文件命名表（核心）

每个事件对应一个**固定基础名**（不含扩展名），大小写不敏感：

| 事件语义 | 文件名 | 循环 | 多首怎么办 |
|---|---|---|---|
| 大厅 / 主菜单 | `hall` | 循环 | `hall_2` / `hall_3` 随机 |
| 角色选择 / 交易 | `choose_part` | 循环 | `choose_part_2` 随机 |
| 加载地图（**第 1 层**） | `waiting_map_1` | 不循环 | 固定一首，不要加后缀 |
| 加载地图（**第 2 层及以后**） | `waiting_map_2` … `waiting_map_12` | 不循环 | 接着编号（`waiting_map_2`、`_3`、`_4`…），每层随机抽一首 |
| 进入地图（比赛开始） | `in_map` | 不循环 | `in_map_2` 随机 |
| 攻击 / 受伤 | `attack_hurt` | 循环 | `attack_hurt_2` 随机 |
| 辐射线出现 | `articulos` | 循环 | 固定一首 |
| 濒死 | `articulos_2` | 循环 | 固定一首；只有 `articulos` 时两者共用 |
| 暂停 / 比赛结束 | `suspend` | 循环 | `suspend_2` 随机 |
| 死亡 / 死亡视角 | `die` | 不循环 | `die_2` 随机 |
| 结局 1（失败） | `final_result_1` | 不循环 | `final_result_1_2` 随机 |
| 结局 2（胜利） | `final_result_2` | 不循环 | `final_result_2_2` 随机 |
| 结局 3 / MVP | `final_result_3` | 不循环 | `final_result_3_1` / `_3_2` 随机（内华达就是这样） |

> 完整 11 个事件、12 个设置项。加载地图音乐的 `waiting_map_*` 全部共用同一个设置项「加载地图界面音乐」与同一条音量滑条。

### ⚠ 加载地图音乐的特殊之处

`waiting_map` 后面的**数字是「槽位」，不是「段号」**：

```
waiting_map_1       第一层专用（行动开始）
waiting_map_2       第二层及以后的随机池 · 第 1 首
waiting_map_3       随机池 · 第 2 首
waiting_map_4  …    随机池 · 第 3、4… 首（一直往后接，编号连续）
```

**绝对不要写 `waiting_map_1_1`、`waiting_map_2_1` 这种「两个数字」的名字。**
`waiting_map_2` 里的 `2` 已经表示「第二层及以后」，再叠一层段号会让人和程序都分不清是「第 1 层第 1 首」还是「第 11 首」。

曲目多于 4 首时继续 `waiting_map_5`、`waiting_map_6`… 一直排到 `waiting_map_12`，
**全部平铺在音乐盒根目录，不要建子文件夹**。

旧命名（`waiting_map_1_1`、`waiting_map_2_1`）在代码里仍能识别（按分段随机处理），但新做的音乐盒请一律按本规则。

## 3. 支持的音频格式与优先级

同一基础名存在多种格式时，按下面顺序取第一个：

```
.mp3  >  .wav  >  .ogg
```

- **不支持 `.flac`**（Unity 2022 与该游戏的加载器都没有 FLAC 解码器）。遇到 `.flac` 会记日志并回退游戏默认，请先转成 mp3。
- 采样率/位深无限制，模组交给 Unity 解码。

---

## 4. 结尾静音会自动跳过

加载音频时会自动检测**结尾**是否有一段“完全无声音”的空白（阈值约 −62 dBFS），
有就裁掉，再交给播放器：

- **循环曲**（`hall` / `choose_part` / `attack_hurt` / `articulos` / `suspend`）：
  循环区间变成「开头 → 最后一个有声样本」，不会再每圈末尾干静几秒。
- **一次性曲**（`waiting_map_*` / `in_map` / `die` / `final_result_*`）：
  播到音乐真正结束就停，接着走下一个事件，不需要等完静音。
- 裁切只在内存里进行，**不会改动 data 里的音频文件**；日志会打印
  `结尾静音已跳过：xxx.mp3 原长 182.3s → 176.9s（裁掉 5.40s）`。
- 静音尾巴不足 0.5 秒不裁；整首都是静音则不裁（保持原样）。

因此你**不需要**自己先把音频尾巴剪干净。

## 5. 多首随机（分段）规则

除「加载地图」用槽位编号外，其他事件的多首写法是「基础名 + `_数字`」：

```
final_result_3.mp3        ← 主文件（存在时优先，分段被忽略）
final_result_3_1.mp3
final_result_3_2.mp3      ← 主文件不存在时，在这两首里随机
```

规则：

1. 若存在无后缀主文件（如 `final_result_3.mp3`），**优先用它**，分段被忽略。
2. 若主文件不存在但存在 `_1 / _2 / …`，**随机选一个**播放，日志会打印「分段命中」。
3. 后缀必须是纯数字，`_a`、`_final` 之类不算分段。
4. `articulos` 与 `articulos_2` 是**两个不同事件**（辐射线 / 濒死），不是随机分段，请分别提供。

---

## 6. 容错规则（模组会自动处理）

| 情况 | 行为 |
|---|---|
| 文件名多一个空格（`waiting_map_1 .mp3`） | 自动宽松匹配并记录日志 |
| 大小写不同（`Hall.MP3`） | 自动匹配 |
| 某事件缺文件 | 该事件回退**游戏原版音乐**，日志记录一次，不影响其它事件 |
| 缺 `waiting_map_2..12` | 回退用 `waiting_map_1` |
| 缺 `waiting_map_1` | 从 `waiting_map_2..12` 里随机借用一首 |
| 整个音乐盒缺失 | 回退「游戏默认」，配置保留，文件夹放回即恢复 |
| 编号不连续（有 `_2` 没 `_3`） | 不影响播放，池子就按实际存在的文件随机 |

## 7. 从 CS2 音乐盒素材到本模组的映射

以 `D:\Downloads\理由-Rad Cat` 里的原始文件为例（典型的网盘下载命名，带中文序号和 Av 号）：

| 原始文件名（截断） | 目标文件名 | 备注 |
|---|---|---|
| `...- 1.主界面(Av…,P1).mp3` | `hall.mp3` | |
| `...- 2.MVP(Av…,P2).mp3` | `final_result_3.mp3` | 有两首就写 `final_result_3_1/_2` |
| `...- 3.比赛结束(Av…,P3).mp3` | `suspend.mp3` | |
| `...- 4.比赛开始(Av…,P4).mp3` | `in_map.mp3` | |
| `...- 5.队伍选择(Av…,P5).mp3` | `choose_part.mp3` | |
| `...- 6.回合开始-1(Av…,P6).mp3` | `waiting_map_2.mp3` | 第二层及以后随机池第 1 首 |
| `...- 7.回合开始-2(Av…,P7).mp3` | `waiting_map_3.mp3` | 随机池第 2 首 |
| `...- 8.回合胜利(Av…,P8).mp3` | `final_result_2.mp3` | |
| `...- 9.回合失败(Av…,P9).mp3` | `final_result_1.mp3` | |
| `...- 10.回合十秒倒计时(Av…,P10).mp3` | `articulos.mp3` | 辐射线出现时 |
| `...- 11.死亡视角(Av…,P11).mp3` | `die.mp3` | |
| `...- 12.行动开始-1(Av…,P12).mp3` | `waiting_map_1.mp3` | 第一层专用 |
| `...- 13.行动开始-2(Av…,P13).mp3` | `waiting_map_4.mp3` | 接着现有最大编号往后排（此处池子已有 `_2` `_3`） |
| `...- 14.炸弹安放(Av…,P14).mp3` | `attack_hurt.mp3` | |
| `...- 15.炸弹十秒倒计时(Av…,P15).mp3` | `articulos_2.mp3` | 濒死时 |

> 第 10 段与第 15 段在本游戏里语义不同：`articulos` 用于辐射线出现，`articulos_2` 用于濒死。
> 如果音乐盒里只有一个 `articulos`，两种场景都会用它。

### 一键重命名（PowerShell）

把素材文件夹里的文件按上表改名，输出到 mod 的 `data\<音乐盒名>\`：

```powershell
$src  = 'D:\Downloads\理由-Rad Cat'
$dest = 'D:\Application\游戏\Casualties Unknown V1.0.2\BepInEx\plugins\UnknownCasualtiesMusicBox\data\理由-Rad Cat'
New-Item -ItemType Directory -Force -Path $dest | Out-Null

# 原始序号 -> 目标基础名
$map = @{
  1='hall'; 2='final_result_3'; 3='suspend'; 4='in_map'; 5='choose_part'
  6='waiting_map_2'; 7='waiting_map_3'; 8='final_result_2'; 9='final_result_1'
  10='articulos'; 11='die'; 12='waiting_map_1'; 13='waiting_map_4'
  14='attack_hurt'; 15='articulos_2'
}

Get-ChildItem $src -File -Filter *.mp3 | ForEach-Object {
    # 只取第一个「1~2 位数字 + 点」作为序号，避开 “CS2”“Av1450263065” 这类噪声
    if ($_.Name -match '(\d{1,2})\.') {
        $idx = [int]$Matches[1]
        if ($map.ContainsKey($idx)) {
            Copy-Item $_.FullName (Join-Path $dest ($map[$idx] + '.mp3')) -Force
        }
    }
}
Get-ChildItem $dest -Recurse -File | Select-Object FullName, Length
```

## 8. 旧数据批量整改

仓库自带脚本 `tools\normalize_waiting_map.ps1`，把旧的双数字命名一次性整理成新规则：

```powershell
# 只看计划
powershell -ExecutionPolicy Bypass -File tools\normalize_waiting_map.ps1 -DryRun
# 实际执行（不删文件，只把编号排成 1..N）
powershell -ExecutionPolicy Bypass -File tools\normalize_waiting_map.ps1
```

规则：`waiting_map_1_1` → `waiting_map_1`，其余依次接在后面编号；
`waiting_map_2_1/_2_2/_2_3` → `waiting_map_2/_3/_4`，
再往后的（例如 `waiting_map_1_2`）继续排成 `waiting_map_5`、`_6`…
最终一定是 `waiting_map_1 … waiting_map_N` 连续编号，全程不新建子目录。

> 如果你装过早期开发版、音乐盒里已经出现了 `_extra\` 子目录，先跑一次
> `tools\merge_extra_back.ps1` 把里面的曲目并回主目录（它同样会自动接着编号），再跑上面的脚本。

## 9. 检查清单（交付前自查）

- [ ] 文件夹名 = 想显示的音乐盒名，且不与已有文件夹重名（忽略大小写）。
- [ ] 基础名齐全：`hall` / `choose_part` / `waiting_map_1` / `waiting_map_2` / `in_map` / `attack_hurt` / `articulos`（+ 可选 `articulos_2`） / `suspend` / `die` / `final_result_1` / `final_result_2` / `final_result_3`。
- [ ] **没有 `waiting_map_1_1` 这类双数字文件名**。
- [ ] `waiting_map_*` 编号从 1 连续排到 N，并且全部平铺在音乐盒根目录（无子文件夹）。
- [ ] 全部为 `.mp3` / `.wav` / `.ogg`，没有 `.flac`。
- [ ] 文件名无前后空格、无全角字符。
- [ ] 进入游戏 → 设置 → 音频 → 选择该音乐盒，日志出现 `音乐盒“X”文件检查：11/11 个事件可用`。

## 10. 常见错误

| 现象 | 原因 |
|---|---|
| 选完没声音，日志「11 个事件可用」但没播 | 游戏音量/音乐音量滑条为 0 |
| 某个事件放原版 | 该事件文件缺失（日志 `事件音频不可用`） |
| 音乐盒列表里没有新文件夹 | 未重启游戏（扫描只在启动时进行） |
| 两个音乐盒只显示一个 | 文件夹名仅大小写不同 |
| 加载音乐每次都一样 | 随机池里只有 `waiting_map_2` 一首，再加 `waiting_map_3` 等即可 |
| 分段不随机 | 同时存在无后缀主文件，主文件优先 |
