## 未知伤亡音乐盒 v1.3.3

### 修复

- **回主菜单时原版音乐与「进入地图音乐」同时播放**：从世界退回主菜单会重载菜单场景，原版菜单音乐重新开始播，而 `in_map` 因为优先级更高还在放，两者叠在一起，等 `in_map` 播完又被大厅音乐顶掉。现在跨出世界时会作废世界内事件状态并主动停掉原版菜单音源，`in_map` 走正常淡出、大厅音乐立刻接管。
- **菜单里原版音乐偶发漏出**：压掉原版菜单音乐的判断从「大厅/角色选择在播」放宽为「任意音乐盒音乐在出声」，避免只有 `in_map` 或 `choose_part` 在播时原版插进来。
- **联机模组拆开「选择角色 / 选择难度」界面后偶尔插入一段原版音乐**：菜单状态识别新增联机大厅面板（`Together.LobbyCharacterPanel`）探测，不再误判成「大厅」来回切歌。

### 变更：加载地图音乐改用槽位编号

旧的 `waiting_map_1_1`（层号 + 段号，两个数字）容易混淆，现在统一成：

| 文件名 | 含义 |
|---|---|
| `waiting_map_1` | 第一层（行动开始），固定一首 |
| `waiting_map_2` … `waiting_map_12` | 第二层及以后的随机池，每次加载随机抽一首 |

- 不再创建 `_extra` 之类的子目录，多出来的曲目直接往后编号（`waiting_map_4`、`_5`…）。
- 旧命名仍然兼容（按分段随机处理），已发布的音乐包已按新规则重打包。
- 仓库新增 `tools/normalize_waiting_map.ps1`，可一键把旧目录整理成连续编号。

### 新增：结尾静音自动跳过

加载音频时会检测结尾「完全无声音」的空白段（约 −62 dBFS）并在内存中裁掉：

- 循环曲的循环区间变成「开头 → 最后一个有声样本」，不会每圈末尾多静几秒；
- 一次性曲播到音乐真正结束就停，立刻接下一个事件；
- 不超过 0.5 秒的静音不裁，改动只发生在内存里，不动 data 里的文件。

### 修复：泡在液体里音乐会「放一段→停→过一会又从头放」

溺水伤害是间歇性的，原来只靠「8 秒内受过伤」判定，窗口一过就淡出、下次掉血又从头播。现在把 `Body.inWater` 也算作受伤状态，并增加 4 秒退出保持，泡在水里时音乐会连续播放。
